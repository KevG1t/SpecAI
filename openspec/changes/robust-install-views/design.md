# Design: robust-install-views

## Technical Approach
Refactor the install flow to use the existing `planner` to generate a `ResolvedPlan` instead of hardcoded steps. The TUI will consume `pipeline.ProgressEvent`s via Go channels to dynamically update BubbleTea views. A new asset injection engine will use `go:embed` to package all 21+ `gentle-ai` skills and configurations (generated via a script that replaces `engram` with `sdd-memory`) and deploy them during the setup pipeline phase.

## Architecture Decisions

### Decision: Dynamic TUI Pipeline State
**Choice**: Extend the TUI `InstallModel` to track pipeline progress via `pipeline.ProgressEvent` streams emitted by the Orchestrator, discarding the static 3-state enum.
**Alternatives considered**: Polling a shared pipeline state object.
**Rationale**: Streaming events directly to a BubbleTea channel receiver aligns with the Elm architecture, avoiding UI blocking and lag.

### Decision: Asset Extraction and Storage
**Choice**: Create a `go:generate` script to extract `gentle-ai` assets from the local filesystem, rewrite the `engram` references, and store them in an `assets/` folder, which is then compiled into the binary using `go:embed`.
**Alternatives considered**: Downloading assets at runtime or hardcoding local paths in the final binary.
**Rationale**: `go:embed` ensures the CLI remains a portable, self-contained binary while still perfectly capturing the source of truth from `gentle-ai`.

### Decision: Planner Integration
**Choice**: Update `internal/tui/model.go` to invoke `planner.NewResolver` with a full component selection (skills, personas, MCPs), and map the `ResolvedPlan` into dynamic `pipeline.Step`s.
**Alternatives considered**: Keep `steps.NewStepInstallGlobalSkills` but hardcode the 21+ new skills inside it.
**Rationale**: Leveraging the Planner ensures topological sorting and soft ordering rules (e.g., Persona before SDD) are naturally respected during injection.

## Data Flow
    Install Screen ──→ TUI Model ──→ Planner (Resolves DAG)
         ↑                  │
         │                  v
    View Update ←── Orchestrator (Executes StagePlan)
         ↑                  │
         └───────── Asset Injector (Reads go:embed assets/)

## File Changes
| File | Action | Description |
|------|--------|-------------|
| `scripts/extract_assets.go` | Create | Script to extract `gentle-ai` assets, rewrite `engram` to `sdd-memory`, and output to `assets/`. |
| `assets/...` | Create | The target directory for embedded `gentle-ai` assets. |
| `internal/tui/screens/install.go` | Modify | Remove 3-state enum. Render dynamic list of tasks using `pipeline.ProgressEvent`. |
| `internal/tui/model.go` | Modify | Replace static `StagePlan` with one generated by `planner.Resolver`. |
| `internal/steps/inject_assets.go` | Create | New pipeline step that unmarshals embedded assets based on the `ResolvedPlan`. |
| `internal/steps/global_skills.go` | Delete | Replaced by the modular `inject_assets.go` step. |

## Interfaces / Contracts
```go
// internal/steps/inject_assets.go
package steps

import "github.com/KevG1t/SpecAI/internal/planner"

// AssetInjector handles unpacking embedded files to the target workspace
type AssetInjector interface {
	Inject(targetDir string, plan planner.ResolvedPlan) error
}
```

## Testing Strategy
| Layer | What to Test | Approach |
|-------|-------------|----------|
| Unit | `extract_assets.go` | Verify `engram` string replacement and exact copy behavior in a temp dir. |
| Unit | `inject_assets.go` | Assert embedded files are written to the correct destination paths using afero memory fs. |
| Integration | Planner + Orchestrator | Ensure `ResolvedPlan` translates correctly to `StagePlan` steps without panics. |
| E2E | TUI Install Flow | Run the CLI in a test harness and verify dynamic progress output and file creation. |

## Migration / Rollout
No migration required. The new asset injection engine will overwrite existing global skills, which acts as a desired upgrade path for users with the old 3 skills.
